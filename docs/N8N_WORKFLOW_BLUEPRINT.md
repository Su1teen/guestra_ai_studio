# Dedicated Guestra Studio orchestration blueprint

No workflow is created/imported/published by this delivery. Build a dedicated workflow in existing Railway `gentle-reprieve` n8n; preserve all other workflows and the existing Telegram outbound webhook. Studio and n8n communicate over authenticated HTTPS across projects. The installed n8n version/publication API must be inspected in the next authorized task.

## Workflow A — guest input

| ---------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1 Webhook Trigger                        | POST on a new unique `guestra-studio` path; Header Auth credential `Authorization: Bearer <N8N_TOKEN>`; response via Respond to Webhook, not immediate generic acceptance                                                                                                                                                                                                                      |
| 2 Validation (Code / schema subworkflow) | Validate studio-gateway-v1, expected environment=test/sandbox, inboundOwner=n8n, channel=simulator, exact workspace/property/tenant mapping, run/message/correlation IDs, 128KiB maximum, declared media metadata and immutable prompt hash                                                                                                                                                    |
| 3 HTTP Request: durable claim            | POST `<STUDIO_PUBLIC_URL>/api/integrations/n8n/claims`, separate stored header credential, body `{executionId:$execution.id,envelope:<original envelope>}`. | 4 Respond to Webhook                     | Return committed receipt `{accepted:true,durablyClaimed:true,runId,payloadHash,duplicate,...}` quickly, before LLM/tools. | 5 IF owner / duplicate                   | `execute=true` owns the new logical run. `execute=false` stops a new duplicate execution, fetches existing Studio receipt and replays latest saved callback if needed. | 6 HTTP Request: CRM inbound              | Exactly one owner POSTs `/messages/inbound` with original `inbound`. Stable externalMessageId/externalUpdateId survive all HTTP retries. | 7 HTTP Request: media references         | After inbound returns actual attachment IDs, register clean, owned externalFileId mapping through `/v2/media/:id/reference`. | 8 HTTP Request: CRM v2 context           | GET `/v2/context` with property/channel/externalUserId/CRM conversation; validate identity and operationalAuthority. Hash/reference this context version in run event                                                                                                                                                  |
| 9 IF human ownership                     | When aiReplyAllowed=false or automationMode != ai, send `human_owned`, stop AI/tools. Recheck before each business tool and final outbound. | 10 AI Agent + approved model             | Immutable prompt snapshot/model/version; legacy tool aliases normalized with the typed approvedTools mapping, then intersected with authoritative allowedActions and configured allowlist. Staff notes/tester annotations/hidden reasoning are excluded. CRM context is authoritative memory for each message                                                                                  |
| 11 Tool subworkflows                     | Runtime validate each tool input and confirmed action evidence; server-set identity/property and stable operation keys. Only CRM facade endpoints below. Include sanitized correlationId/executionReference/promptVersion/deploymentReference query fields (CRM trace middleware reads these); emit safe tool/business events without raw arguments/secrets                                    |
| 12 HTTP Request: operation receipt       | For pending, poll GET `/v2/operations/:id` with original identity; Wait between bounded attempts. Completed requires authoritative snapshot. Rejected displays safe decline/requote reason; unknown completion suspends execution for recovery                                                                                                                                                 |
| 13 HTTP Request: outbound prepare        | POST `/v2/messages/outbound/prepare`, stable reply/proposal key, same conversation, allowlisted ready+clean mediaReferenceIds. A proposal is not delivered yet                                                                                                                                                                                                                                 |
| 14 Delivery adapter + CRM result         | Actually deliver to simulator/channel. POST `/messages/outbound/result` with the transport result. HTTP 200/success:false is delivery failure. Never submit fake sent/delivered to satisfy guest consent                                                                                                                                                                                       |
| 15 Safe completion                       | Read authoritative changes/operation/context evidence; send sequenced signed reply_delivered/completed callback. Business operation still pending cannot become completed. Studio independently checks business receipt; guest delivery bubbles come from CRM changes                                                                                                                          |

The [Webhook node](https://docs.n8n.io/integrations/builtin/core-nodes/n8n-nodes-base.webhook) provides separate test/published production URLs and header authentication. Use [Respond to Webhook](https://docs.n8n.io/integrations/builtin/core-nodes/n8n-nodes-base.respondtowebhook) after the committed claim; publishing a workflow does not turn the supplied business production URLs into sandboxes. [HTTP Request](https://docs.n8n.io/integrations/builtin/core-nodes/n8n-nodes-base.httprequest) supports credential-backed requests and tools; disable redirects/SSL bypass, preserve HTTP status and independently validate JSON/business state. The [AI Agent](https://docs.n8n.io/integrations/builtin/cluster-nodes/root-nodes/n8n-nodes-langchain.agent) must receive only approved tool subworkflows; no arbitrary SQL/HTTP write tool.

Every confirmed mutation requires a genuinely delivered proposal, later guest confirmation message, matching canonical payload, current AI ownership, allowed action, valid quote/revision/property and stable operation key. CRM signs its own PMS command and performs owned PMS read-back. **Studio/n8n never get PMS_COMMAND_SECRET or direct PMS write credentials.** Do not implement payment capture/refund here. Pending payment, provider authorization, reservation confirmation and settled money are distinct facts.

## Stable envelope, retry and events

Preserve existing studio-gateway-v1 keys: contractVersion, environment, workspaceId, conversationId, runId, correlationId, inboundOwner, inbound, media, prompt. Add externalMessageId, payloadHash and property `{crmPropertyId,crmTenantId,pmsPropertyId,pmsTenantId}`. `Idempotency-Key` is `<workspace>:<conversation>:<externalMessageId>`.

Canonical SHA-256 recursively sorts object keys by Unicode/codepoint order, omits undefined object members, preserves array order, and JSON-serializes primitives. Hash all envelope fields **except payloadHash**, and remove only `media[].url` before hashing; short-lived URLs may be exchanged without changing logical input. Full stable prompt/configuration/media metadata and property scope remain in the hash. JSON schema/algorithm live in `server/gateway-contract.ts`; do not replace with raw-JSON-byte hashing. Business keys should be <=120 characters, derived from SHA-256 of workspace/run/tool/logical action/proposal/confirmation; retries reuse original keys and never invent a new booking key.

Webhook delivery is at least once. A durable Studio claim prevents duplicate logical owners; native CRM/PMS operation receipts provide exactly-once business effects. Neither n8n webhook nor an in-memory node/static variable guarantees exactly-once. Lost HTTP responses trigger capped exponential retries with the frozen envelope/keys; acceptance without claim is rejected. Studio eventually records completion_unknown and blocks that conversation when completion cannot be established. Recover using GET `/api/integrations/n8n/runs/:id?workspaceId=...`, original n8n execution and CRM receipt; restarting delivery must not rerun a committed business mutation.

Callback POST `<STUDIO_PUBLIC_URL>/api/integrations/n8n/events` with exact raw application/json, `x-studio-timestamp` epoch seconds, `x-studio-signature` lowercase hex HMAC-SHA256(secret, timestamp + '.' + rawBody). Five-minute clock window. Body:

```json
{
  "eventId": "UUID",
  "workspaceId": "approved-workspace",
  "runId": "UUID",
  "correlationId": "UUID",
  "executionId": "claimed-n8n-execution",
  "sequence": 1,
  "crmConversationId": "verified-crm-id",
  "crmCustomerId": "verified-customer",
  "state": "inbound_saved"
}
```

States: dispatch_accepted, inbound_saved, agent_processing, tool_execution, business_pending, business_completed, reply_prepared, reply_delivered, completed, failed, human_owned, completion_unknown. Optional safe fields: businessOperationId, workflowVersion, deploymentId, contextVersion, uppercase errorCode. Sequence increases per run and event IDs/payloads are immutable; changed event ID payload conflicts. Keep original ID/body for event replay, renew timestamp/signature. Late sequences cannot regress terminal state. Human ownership is sticky. Failure while a business outcome remains unknown suspends recovery instead of freeing another booking. Signed events never themselves create guest delivery receipts. Callback persistence survives a CRM read outage; normal polling reconciles later.

## Workflow B — capabilities

New unique authenticated GET webhook `guestra-studio-capabilities`, Respond to Webhook with studio-gateway-v1/environment/inboundOwner=n8n/durableClaim=studio-claim-v1, **real** authorized workflowId/deploymentId, exact property mapping and workspaceIds. Verify the target workflow's active published metadata before responding. Missing/unpublished workflow returns WORKFLOW_NOT_DEPLOYED; n8n UI/health is not capabilities. Prompt deployment status requires the separate publisher's verified read-back, not this general response.

## Workflow C — errors/recovery

Use a dedicated Error Trigger workflow associated only with the new Studio workflow. Correlate the original claimed execution/run; read Studio receipt and CRM operation before retry. Send only safe error codes and signed monotonic callbacks. Original run not claimed means no accepted request. Error branches for AUTH/SCOPE/ENVIRONMENT/CONTRACT stop without retries; PRICE_CHANGED/QUOTE_EXPIRED require a new guest proposal; REVISION_CONFLICT/IDENTITY_CONFLICT require fresh read-back/human review; 429/5xx/timeouts use bounded original-key retries. A generic 'retry execution' action must preserve native keys and ownership. [n8n error handling](https://docs.n8n.io/build/flow-logic/handle-errors-gracefully.md) and [execution retries](https://docs.n8n.io/workflows/executions/all-executions/) describe facilities, not business idempotency guarantees.

Execution logging is supplementary diagnostics: keep correlation/run/message/operation/workflow/deployment IDs, HTTP status/retry/latency and prompt/context hashes; exclude secrets, signed URLs, staff notes, raw payment tokens, guest payloads and hidden reasoning. Configure retention/redaction with the operator; CRM/Studio remain authoritative history. Review [execution environment variables](https://docs.n8n.io/hosting/configuration/environment-variables/executions/) for save/prune settings.

## Credentials, publication and workers

Create dedicated n8n credential records for Studio webhook/claim bearer, callback HMAC, CRM scoped sandbox principal, media scanner/storage exchange and approved model provider. Configuration values: STUDIO_PUBLIC_URL, CRM_AGENT_BASE_URL, exact CRM/PMS property/tenant/environment/workspace IDs, approved workflow ID/deployment version, timeout/retry budget and tool allowlist. Store these in approved credential/config providers; access from Code nodes must follow the installed instance policy, never disable global restrictions for other workflows.

A future PromptPublisher uses n8n metadata/API only with server-side authorization, workflow allowlist, prompt hash read-back and rollback. [API authentication](https://docs.n8n.io/connect/n8n-api/authentication.md) uses a dedicated API key; verify available scopes/version before implementation. [Save/publish](https://docs.n8n.io/build/understand-workflows/save-and-publish-workflows.md) distinguishes saved changes from published execution. Follow [credential management](https://docs.n8n.io/credentials/) and avoid secrets in exports. No API key/workflow mutation is performed now.

Keep existing n8n execution mode in this task. [Queue mode](https://docs.n8n.io/deploy/host-n8n/configure-n8n/scaling/enable-queue-mode.md) uses Redis/workers with shared instance encryption configuration; moving the shared instance to queue mode requires a separate operator rollout that protects other workflows. Queue workers do not replace Studio's durable claims, per-conversation order or CRM/PMS receipts. Prefer authorized media references/exchange over binary payloads in JSON or worker-local files.
